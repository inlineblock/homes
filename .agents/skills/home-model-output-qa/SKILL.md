# Home model and output QA

Work from the repository root; paths below are repository-relative. Read applicable AGENTS.md, the home’s README, `project.json`, `program.md`, and `design-review.md`. Apply [design standards](../../../docs/home-design-standard.md), [program checklist](../../../docs/home-program-checklist.md), relevant [design-guide chapters](../../../docs/design-guide/README.md), and [asset adoption rules](../../../docs/assets.md); keep climate and tier decisions there rather than duplicating them here.

## Preserve and coordinate

Inspect Git status and native-file changes before regeneration. Preserve manual work; never overwrite an unpreserved edited model. Read the home’s authoring instructions to identify overwritten files and exact regeneration commands. Coordinate binary ownership and serialize heavy GPU rendering with other agents when needed. Discover installed Blender/Bonsai and document runtimes; record tested versions and commands without baking one machine’s paths into reusable tools. If the environment requires escalation for Blender, use its approval mechanism; this skill grants no additional commit, publication, or installation authorization.

For a gallery-only task, preserve approved geometry, materials, lights and layout. Inventory existing reviewed outputs first, add only missing camera views, and verify native reopening plus camera/source consistency. Do not force a whole-home redesign or regenerate unchanged IFC and drawings solely to add a README image. Record any design limitations revealed by the new angle.

## Validate the actual scene

Use the home’s dimensional source for geometry, drawings, and area schedules. Pin linked asset versions in `project.json` and `assets/README.md`; follow the library contribution workflow for missing repeated parts.

Reopen the saved native file in a fresh Blender process and run its home-specific verifier. Check measured floor areas and exclusions, storey datums, rooms, modeled bedroom storage, parked-car/pedestrian routes, welcoming arrival, furniture operation, and access to every room. Include appliance and cabinet door opening envelopes, stairs/landings/headroom/guards, moving glazing at intermediate states, and deck support/terrain contact where applicable. Test evaluated linked-instance geometry, not merely object names or empty instance bounds. A collision-free narrow corridor is not proof of a pleasant entry. Record unresolved checks honestly.

[Repository verification](../../../tools/common/verify_repository.py) checks native reopening, relative dependency paths, floor area, bed counts, asset-schedule presence and actual adoption against manifest pins without rewriting receipts. Run it in a clean session with `blender --factory-startup --background --python-exit-code 1 --python tools/common/verify_repository.py` so local add-on workspace links do not contaminate the result. It does not prove the full design standard or migrate local repeated objects automatically. Confirm LFS files are real models rather than pointer stubs and dependencies remain inside the checkout.

Export the intended envelope state through [IFC export](../../../tools/common/export_scene_ifc.py); inspect collection classification and storey mappings for this home. Reopen and schema-check the IFC, then use [Bonsai verification](../../../tools/common/verify_bonsai.py) in a separate process. Do not save temporary render/cutaway/export states over the canonical furnished model. Distinguish classified concept geometry from a complete semantic building model.

## Review before promotion

Generate drafts in ignored `outputs/work/`. Inspect actual front/arrival, rear/outdoor, side or elevated roof/site views, and relevant interiors. Reject visibly toy-like results: flat materials, repeated texture patterns, sharp un-beveled edges, opaque-looking glass, floating objects and dead or clipped lighting. Inspect close-up material detail as well as overall composition; improve the scene before relying on Image Gen. Check mutual consistency, roof drainage concept, ground contact, floating plants, obstructing foliage, believable furniture/material scale, hardware placement, glazing, light exposure, and camera composition. Compare opening states from identical cameras when demonstrating movement. Generated illustrations cannot stand in for native model renders.

Check whether features communicate their actual intended use: a low roof must not casually read as an accessible terrace with no access, a glazed bay must not imply a nonexistent floor, and a shade pergola must not be presented as weatherproof shelter. Resolve misleading geometry, composition or captions against the brief; do not automatically add a terrace or extra storey.

Render PDF pages to images and inspect every page alongside its furnished plan: dimensions, labels, fixtures, openings, circulation, clipping, and embedded images must match the current scene. Fix defects and regenerate affected artifacts before promotion.

Promote only reviewed images and documents into stable `outputs/images/` and `outputs/plans/` filenames. Refresh dependent boards/previews, output index, home/root galleries, manifest, asset schedule, and design-review evidence together. Keep no output history/version folders; Git retains revisions. Report exactly which checks passed and which remain unresolved; neither rendering nor schema validation establishes engineering, code, or permit approval.

## Image Gen after native render review

Sequence: **model → reviewed native renders → Image Gen edits → visual comparison → current gallery**. For a new or substantially revised home, finish this pass after the affected native views are approved and before declaring the gallery complete. For a scoped edit, refresh only studies whose source views changed; retain unchanged reviewed studies.

Plan abundant useful coverage, not a single hero plus optional interiors. For a full home, normally aim for **6–10 distinct photographic studies**, adding more wherever another room, angle, operating state or detail helps explain the design. This is a planning default, not a cap, and does not trigger a gallery rebuild for a narrow edit. Cover front/arrival, rear/outdoor living and side/roof/site; kitchen and living interiors; and every crowning feature. Add baths, bedrooms, courtyard, fireplace, pool, deck, material details and dusk views when applicable and informative. Avoid padding the tour with near-identical crops. Record planned source views and any remaining coverage gaps in the design review; do not claim a full tour when only the hero is done. When auditing older homes, state their actual photographic coverage and migration work separately from passing native-gallery checks. Use the project's real program: a garage/game-room project needs its activity spaces, not an invented dwelling kitchen.

1. Select the reviewed native source views for the photographic tour. If an important view is missing, render and review it first. Read the available `imagegen` skill for tool usage. Use the built-in Image Gen editing tool by default; do not substitute a text-only generation or silently switch to an API/CLI. Inspect each source image first and supply its actual local path using `referenced_image_paths`. One source view per study keeps the camera unambiguous.
2. Ask for a believable architectural photograph of **the same design and view**. Lock massing, roof slopes, floor count, openings, frame/post/beam positions, furniture layout, material palette, designed site grades and operating states. Improve light, reflections, material texture and photographic realism without adding architecture or changing furniture. When the native setting is sparse, enrich the surrounding landscape with plausible trees, planting, ground cover and distant context so the home feels situated. Preserve designed paths, driveways, pools, terraces, access, important trees and ground contact; keep additions clear of architectural features and maintain a coherent setting across angles. Treat added landscape as illustrative context, not surveyed conditions or modeled scope, and disclose it in provenance. Name the view's important constraints, such as a wall-attached pergola with no house-side posts or matching exposed interior timber.
3. Inspect the generated image beside its source. Check geometry and material drift, invented doors/storeys/terraces, missing supports, changed furniture and lost signature details. Correct architectural mismatches with focused Image Gen edits and review again before selection. Do not remove plausible contextual landscaping merely because it is absent from a sparse native scene; check that it complements the intended setting and preserves usable outdoor spaces. If the architecture itself needs improvement, fix the model and rerender first; an attractive generated deviation is not an approved model change.
4. Save the selected file under stable `outputs/images/` names, for example `photo-hero.png` and `photo-interior.png`. Keep rejected attempts in ignored `outputs/work/`. Record the actual prompt, tool, source-render path, source SHA-256, selected-image SHA-256 and any material limitations in `outputs/photo-study.md` or a view-specific provenance file. Use [Coastal House's manifest](../../../homes/coastal-house/gallery.json) and [interior provenance](../../../homes/coastal-house/outputs/photo-interior-study.md) as format examples, not copied evidence.
5. Register the lead exterior under `photographic_hero`, additional exteriors under `photographic_exteriors`, and interiors under `photographic_interiors` in `gallery.json`, with paths relative to the home and actual hashes. Lead the home README, output index and root catalog entry with the labeled exterior photographic study. Embed all selected studies with descriptive captions in all three locations; pair interior studies with their native source renders. Organize the home page as a readable tour from arrival to shared rooms, outdoor living and details, with plans easy to find. Retain every required native view and plan; generated studies never count as native evidence. Run the gallery verifier and inspect the final image/caption order.

Label results **AI photographic studies**, not photographs of an existing building. If generation is unavailable or fails, report this finishing step as incomplete rather than substituting a native render without explanation. When a source view changes, regenerate its study or explicitly retire the stale one; a completed home still requires a current exterior photographic hero.

## Requested walkthrough videos

When creating, revising or auditing a walkthrough, read [walkthrough guidance](references/walkthroughs.md) for traversable native motion, exact-frame photographic references, AI conditioning, cache validity and separate completion checks. This does not require a video for ordinary still-gallery work.

## Gallery completeness

Apply the [required visual gallery](../../../homes/AGENTS.md#required-visual-gallery), including distinct exterior/interior coverage, every occupied level and clearly pictured signature features. Inventory actual image contents rather than counting filenames or treating cutaways as exterior views. Update each home’s `gallery.json`, embed the selected set directly in its README and output index, and refresh the root catalog. Run [gallery verification](../../../tools/common/verify_galleries.py), then visually check the image/caption sequences and plans. Missing views require reviewed native renders; a passing file count is not visual approval.
