# Handbook maintenance

- Chapters are decision aids, not universal building-code statements. Separate user preferences, internal profiles, primary-source guidance, manufacturer-specific requirements and site/jurisdictional obligations.
- For each new feature explain when to use it, alternatives, interfaces/clearances, climate/maintenance implications, library options or gaps, and required evidence.
- Use primary sources and place readable links beside supported claims. Do not invent numeric standards or imply a rendered assembly has tested performance.
- Keep canonical program requirements in ../home-program-checklist.md; chapters elaborate rather than fork conflicting checklists.
- New broadly reusable geometry must be added to the actual library, previewed, and adopted in a home before claiming reuse. Follow ../assets.md for derivation/version records.
